📝 ThinkPHP 2.x 远程代码执行漏洞实战 Writeup：无引号读环境变量的绝地反击

一、 靶机信息与漏洞简介

· 靶机环境：ThinkPHP 2.1 (Vulhub 环境)
· 漏洞类型：远程代码执行 (RCE)
· 漏洞原理：ThinkPHP 2.x 版本在 Dispatcher.class.php 的 preg_replace 函数中使用了 /e 修饰符，导致在解析路由时，将参数进行了代码执行。攻击者可以通过构造恶意的 s 路由参数，直接执行任意 PHP 代码。

二、 渗透过程详解

1. 初始探路与引号地狱

根据漏洞原理，直接构造 Payload 尝试执行命令。目标环境是容器，已知 Flag 通常藏在环境变量中，因此首选 env 命令。

最初的 Payload：

http
http://direct-ctf2.dasctf.com:25966/index.php?s=/index/index/name/${@system("env")}


踩坑 1：页面直接报错 Parse error: syntax error, unexpected '"env"'...。
原因：在底层拼接时，preg_replace 会将我们的参数拼接到 $var['name']="..." 中。双引号提前闭合了原本的字符串，导致 PHP 语法错误。

踩坑 2：将双引号换成单引号 system('env')。
原因：由于 PHP 底层的转义机制，单引号被转义成了 \'，依然导致语法错误。

2. 绝地反击：无引号大法

既然带引号的 system 命令怎么都会报错，必须换一个不需要传字符串参数的 PHP 函数，并且使用超全局变量来获取环境变量。

终极 Payload（直接丢弃引号和 system）：

http
http://direct-ctf2.dasctf.com:25966/index.php?s=/index/index/name/${@var_dump($_ENV)}


· var_dump()：直接打印变量的详细信息，不需要引号。
· $_ENV：PHP 自带的超全局变量，包含了所有系统环境变量。

3. 收割 Flag

将上述 Payload 丢进浏览器直接访问。页面虽然下方报了“系统发生错误”（因为路由没找到对应的模块），但在页面的最顶部，直接打印出了格式极其优美的环境变量数组：

text
array(38) {
  ...
  ["FLAG"]=> string(42) "CTF2{331707d1-b38f-484b-b55a-7a367115bbba}"
  ...
}


一眼锁定 Flag，完美提交拿分！

三、 总结与反思

1. 关于 /e 漏洞的拼接限制：ThinkPHP 2.x 的 RCE 在实战中经常会遇到引号闭合的问题。在遇到 syntax error 时，不要死磕 system 或 exec，尝试更换不需要参数或支持数组的函数（如 phpinfo、var_dump、print_r）。
2. 超全局变量的妙用：在无回显或者无法执行系统命令的 RCE 环境下，直接使用 var_dump($_ENV) 或 phpinfo() 提取环境变量，往往比辛辛苦苦弹 Shell 找文件要快得多。
3. 容器环境的常态：现在的 CTF 靶机大量使用 Docker/K8s，Flag 直接塞在环境变量里已经成为主流。记住这句口诀：“找不到 Flag，就查环境变量”。
